## Directory conventions
- `WORKFLOW.md` and `FORMAT_STANDARD.md`: authoritative U.S. adaptations of approved European workflow and formatting.
- `editions.json`: canonical manifest kept in sync with the Latest card, dated pages and archive.
- `index.html`: archive landing page and current-edition entry.
- `YYYY-MM-DD/index.html`: canonical dated public web edition, one per issue date.
- `data/incidents-YYYY-MM-DD.json`: public incident records with stable IDs, date, classification and source URLs.
- `assets/readiness.css`: European-parity editorial layout, scoped to U.S. Readiness. The legacy `assets/us-readiness.css` supports the retained long-form analysis page.
- `assets/us-readiness-banner.svg`: lightweight, accessible editorial banner for the site.
- Dated PDFs are stored under `editions/US_Domestic_Readiness_Daily_YYYY-MM-DD.pdf`; the November 16, 2026 PDF has been uploaded and has selectable text and clickable source hyperlinks. Check the existence and link annotations of every future PDF before publishing a download link.

## Editorial controls
1. Cite primary investigators/operators when available; corroborate with reputable reporting.
2. Keep occurrence status, intent, root cause, severity and foreign/state attribution separate.
3. H1 = malicious incident confirmed (not necessarily terrorism or warfare); H2 = hostile activity suspected; D1 = non-hostile disruption with supported cause; D2 = unresolved initiating cause.
4. Maintain a full 60-calendar-day window, retain stable IDs and document corrections. Carry-ins are counted separately from new onsets.
5. Acknowledge gaps. The initial 30 events are a **selective backfill**, not a complete census of all U.S. incidents.
6. Use dates and research-cutoff timezone precisely. Public editions must be source-checked and retain the original cutoff.
7. Never auto-post, email or publish draft material without explicit permission. This is a public archive, not an automated emergency alert.
8. Do not modify the European Readiness Daily folder, workflow or historical editions as part of this publication.

## Release checklist
- Verify source URLs, the latest facts, and all changes since the prior edition.
- Check counts/unique IDs and exclusions for planned activities and contextual watch.
- Produce the final DOCX from the approved Word master, then export and verify the linked PDF. The web edition is a dated PDF viewer and metadata page; an expanded HTML analysis is optional.
- Check the landing page latest link, archive chronology, and research-cutoff metadata.
- Review the GitHub Pages deploy status for the commit.
- Verify hosted PDF bytes, document pages and clickable source hyperlinks. Social distribution follows the European short blurb plus the dated edition URL, not a separate LinkedIn replacement article.
